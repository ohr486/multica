# カスタムランタイム

カスタムランタイムプロファイルを使うと、Multica がサポートするプロトコルファミリーのいずれかを話しつつ、チーム固有のコマンドで起動される AI CLI をワークスペースに登録できます。

## コマンドと引数

ターミナルで実行するのと同じ argv スタイルのコマンドを貼り付けてください。

```sh
agent --model composer-2.5
```

Multica はこれを次のように保存します。

- `command_name`: `agent`
- `fixed_args`: `["--model", "composer-2.5"]`

デーモンは `exec.Command(command_name, fixed_args...)` でプロセスを直接起動します。シェルは実行しません。

サポートされる入力:

- 空白で区切られたプレーンな引数
- スペースを含む値のためのシングルクォートまたはダブルクォート
- リテラルなスペースやクォート文字のためのバックスラッシュエスケープ

UI のパーサーは argv 指向であり、完全な POSIX シェルではありません。ダブルクォート内では、`\` は次の文字を直接エスケープします。`$` やバッククォートをリテラルのまま残す必要がある場合はシングルクォートを使ってください。実行中のタスクは開始時の起動引数を保持します。プロファイルのコマンドや引数の編集は、デーモンが再登録した後に新しくクレームされたタスクへ適用されます。

サポートされない入力:

- パイプ、リダイレクト、`;`、`&&`、`||`
- バッククォート
- `$VAR` または `$(...)` の展開

ランタイムがシェルの挙動を必要とする場合は、ラッパースクリプトを使ってください。

## コマンドが見つからない場合

デスクトップから起動されたデーモンは、対話的なターミナルと同じ `PATH` を継承しないことがあります。コマンドがシェルでは動作するのにカスタムランタイムで登録エラーが表示される場合は、そのマシン上で絶対パスを固定してください。

```sh
multica runtime profile set-path <profile-id> --path /abs/path/to/agent
```

その後、デーモンを再起動またはリフレッシュして、プロファイルを再登録させてください。

## アップグレードの順序

カスタムランタイムの引数と登録エラーの報告には、`fixed_args` の起動仕様と `failed_profiles` の登録レポートをサポートするサーバーとデーモンの両方のバージョンが必要です。混在したデプロイでは、失敗したカスタム専用プロファイルが空のランタイム登録として拒否されるのではなく記録されるように、新しいデーモンを展開する前にサーバーをアップグレードしてください。
